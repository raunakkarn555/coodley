Unit 01

Web Data Protocols

The foundation of how the web communicates. HTTP, HTTPS, WebSockets — understand the plumbing before the paint.

⭐

Most Important for Exam: HTTP methods (GET vs POST), status codes, request-response cycle, difference between HTTP and WebSockets, statelessness of HTTP — these appear in nearly every university exam.

HTTP is a stateless, application-layer protocol used for transmitting hypermedia. The client (browser) sends a request; the server sends back a response. Each request is independent — the server remembers nothing between requests (stateless).

HTTP Request Structure

GET /index.html HTTP/1.1 Host: www.example.com Accept: text/html Cookie: sessionid=abc123

HTTP Methods

MethodPurposeHas Body?Idempotent?
GETRetrieve resourceNoYes
POSTSubmit data / create resourceYesNo
PUTReplace resource completelyYesYes
PATCHPartially update resourceYesNo
DELETEDelete resourceNoYes
HEADGET without response body (check headers)NoYes
OPTIONSAsk what methods are allowed (CORS preflight)NoYes

HTTP Status Codes

✅
2xx — Success
200 OK — request succeeded. 201 Created — new resource created. 204 No Content — success, no body.
↪️
3xx — Redirection
301 Moved Permanently — URL changed forever. 302 Found — temporary redirect. 304 Not Modified — use cached version.
❌
4xx — Client Error
400 Bad Request. 401 Unauthorized. 403 Forbidden. 404 Not Found. 405 Method Not Allowed.
💥
5xx — Server Error
500 Internal Server Error. 502 Bad Gateway. 503 Service Unavailable.

HTTP vs HTTPS

HTTPHTTPS
Port 80Port 443
Plain text — data readableEncrypted via TLS/SSL
No certificate neededRequires SSL certificate
Faster (no overhead)Slightly slower (encryption cost)
Insecure — passwords visibleSecure — passwords encrypted
📝 Exam Trick

GET vs POST: GET sends data in URL (visible, bookmarkable, cached). POST sends data in body (hidden, not cached, suitable for forms). GET is idempotent; POST is not.

WebSockets provide a persistent, full-duplex communication channel over a single TCP connection. Unlike HTTP (request-response), WebSockets allow the server to push data to clients at any time without the client requesting it.

FeatureHTTPWebSocket
CommunicationHalf-duplex (request→response)Full-duplex (both directions simultaneously)
ConnectionNew connection per requestPersistent, single connection
OverheadHigh (headers each request)Low (after handshake)
Server PushNo (only response)Yes
Use CaseNormal web browsing, REST APIsChat, live scores, stock tickers, gaming
Protocolhttp:// or https://ws:// or wss://

WebSocket Handshake: WebSockets start as an HTTP request with Upgrade: websocket header. Server responds with 101 Switching Protocols. After this, the connection switches to the WebSocket protocol.

💡 Memory Trick

Think of HTTP as a walkie-talkie (one speaks, then other) vs WebSocket as a phone call (both can speak simultaneously). Use WebSockets when the server needs to push updates proactively.

Block elements (div, p, h1-h6, section, article) take full width. Inline elements (span, a, img, input) only take as much width as needed. inline-block = inline but can set width/height.

The Box Model

Every HTML element is a box: Content → Padding → Border → Margin (inside out). box-sizing: border-box makes width/height include padding and border — preferred for layouts.

Flexbox — One-Dimensional Layout

CSS — Flexbox
/* Parent (flex container) */ .container { display: flex; flex-direction: row; /* row | column */ justify-content: space-between; /* main axis */ align-items: center; /* cross axis */ flex-wrap: wrap; gap: 16px; } /* Child (flex item) */ .item { flex: 1; /* grow: 1, shrink: 1, basis: auto */ align-self: flex-start; }

CSS Grid — Two-Dimensional Layout

CSS — Grid
.grid-container { display: grid; grid-template-columns: repeat(3, 1fr); grid-template-rows: 100px 200px; gap: 20px; } .item-spanning { grid-column: 1 / 3; /* span 2 columns */ grid-row: 1 / 2; }
📝 Flexbox vs Grid

Flexbox = 1D layout (row OR column at a time). Use for navbars, card rows, centering. Grid = 2D layout (rows AND columns simultaneously). Use for page layouts, dashboards.

Unit 04

JavaScript & jQuery

The language that makes the web interactive. DOM, events, ES6+, and jQuery patterns.

🔥

Guaranteed 20–25 marks: JavaScript DOM manipulation, events, and jQuery appear in every exam. Know getElementById, event listeners, Arrow functions, and jQuery $() selector cold.

JavaScript — DOM & Events
// DOM Selection const el = document.getElementById('myId'); const els = document.querySelectorAll('.myClass'); const first = document.querySelector('h1'); // DOM Manipulation el.textContent = 'New text'; el.innerHTML = '<b>Bold</b>'; el.style.color = 'red'; el.classList.add('active'); el.classList.toggle('hidden'); el.setAttribute('href', '#'); // Events el.addEventListener('click', function(e) { e.preventDefault(); console.log('Clicked!'); }); // ES6+ Features const greet = (name) => `Hello, ${name}!`; // Arrow fn + Template literal const { age, city } = person; // Destructuring const arr = [1,2,...existing]; // Spread operator const doubled = arr.map(x => x * 2); // map/filter/reduce const evens = arr.filter(x => x % 2 === 0); // Promises & Async/Await async function fetchData() { const res = await fetch('https://api.example.com/data'); const data = await res.json(); return data; }
📝 var vs let vs const

var: function-scoped, hoisted, can re-declare. let: block-scoped, not hoisted, can reassign. const: block-scoped, cannot reassign (but objects/arrays can be mutated). Always prefer const, then let. Never use var in modern code.

jQuery
// Document Ready $(document).ready(function() { // or $(function() { // Selectors (CSS-like) $('#myId').text('Hello'); $('.myClass').hide(); $('p').css('color', 'red'); $('input[type=text]').val('Default'); // Events $('#btn').click(function() { $('#result').html('<b>Clicked!</b>'); }); // Effects / Animation $('#box').fadeIn(500); $('#box').slideToggle(300); $('#box').animate({ opacity: 0.5, width: '200px' }, 1000); // DOM Manipulation $('ul').append('<li>New Item</li>'); $('#item').remove(); $('#el').addClass('active').removeClass('inactive'); // jQuery AJAX $.ajax({ url: '/api/data', method: 'GET', success: function(data) { console.log(data); }, error: function(err) { console.error(err); } }); });
💡 jQuery vs vanilla JS

jQuery simplifies cross-browser DOM manipulation. $('#id') = document.getElementById('id'). $('.cls').hide() = document.querySelectorAll('.cls').forEach(el=>el.style.display='none'). jQuery is a library, not a framework.

Unit 05

AJAX, Cookies & Sessions

Asynchronous communication and state management in stateless HTTP.

AJAX allows web pages to update content asynchronously by exchanging data with the server in the background — without reloading the entire page. Despite the name, JSON is now used more commonly than XML.

AJAX Flow

1. User triggers event
User clicks a button, types in a search box, etc.
2. JavaScript creates XMLHttpRequest (XHR)
Or uses modern fetch() API
3. Asynchronous request sent to server
Page continues running — user is not blocked
4. Server processes & responds
Returns JSON, XML, or HTML fragment
5. JavaScript updates DOM
Only the required part of the page is updated
JavaScript — Fetch API (Modern AJAX)
// Modern AJAX with Fetch API fetch('/api/users') .then(res => res.json()) .then(data => { document.getElementById('output').textContent = data.name; }) .catch(err => console.error('Error:', err)); // POST request with fetch fetch('/api/users', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ name: 'Alice', age: 22 }) }).then(res => res.json()).then(console.log);

Why state management? HTTP is stateless — the server forgets each request. Cookies, sessions, and web storage solve the problem of "remembering" users between requests.

Cookies

Small pieces of data (max ~4KB) stored by the browser and sent with every HTTP request to the matching domain. Used for authentication tokens, preferences, tracking.

Cookie AttributeMeaning
Expires/Max-AgeWhen cookie expires. Session cookie = no expiry (deleted on browser close).
HttpOnlyCannot be accessed by JavaScript — protects against XSS
SecureOnly sent over HTTPS
SameSiteControls cross-site sending (Strict/Lax/None) — CSRF protection
Domain/PathWhich domain/path the cookie is sent to

Sessions vs Cookies

FeatureCookiesSessions
StorageClient browserServer (file/memory/DB)
Size limit~4KBUnlimited (server-side)
SecurityLess — client can tamperMore — data on server
ExpiryControlled by Expires/Max-AgeConfigured server-side (e.g. 30 min)
IdentifierFull data in cookieSession ID in cookie; data on server

localStorage vs sessionStorage

FeaturelocalStoragesessionStorage
PersistencePermanent (until manually cleared)Until tab/browser closed
ScopeAll windows/tabs of same originOnly the current tab
Size~5-10MB~5-10MB
Sent to server?No — browser onlyNo — browser only
💡 Memory Trick

Cookie = sent to server automatically. localStorage = browser only, permanent. sessionStorage = browser only, dies with tab. Session = server-side storage identified by a cookie's session ID.

Unit 06

Databases & ORM Tools

Persisting data on the web — from raw SQL to Object-Relational Mapping.

ORM (Object-Relational Mapping) is a technique that maps database tables to programming language classes/objects, allowing developers to interact with the database using code instead of raw SQL.

🐍
SQLAlchemy (Python)
Powerful ORM for Python. Used with Flask. Supports multiple databases. Models = Python classes.
🟢
Sequelize (Node.js)
ORM for Node.js supporting MySQL, PostgreSQL, SQLite. Uses JavaScript classes as models.
🎸
Django ORM (Python)
Built into Django. Models are Python classes. Automatic migrations. Most popular for web dev.
☕
Hibernate (Java)
JPA-based ORM for Java. Used with Spring. Maps Java classes to DB tables via annotations.

ORM CRUD vs Raw SQL

Django ORM vs Raw SQL
# Django ORM — Pythonic, no SQL needed from myapp.models import Student # CREATE s = Student.objects.create(name="Alice", age=21) # READ all_students = Student.objects.all() cs_students = Student.objects.filter(dept="CS") student = Student.objects.get(id=1) # UPDATE student.name = "Bob" student.save() # DELETE student.delete() -- Equivalent Raw SQL SELECT * FROM student WHERE dept = 'CS'; INSERT INTO student (name, age) VALUES ('Alice', 21); UPDATE student SET name='Bob' WHERE id=1; DELETE FROM student WHERE id=1;

Transaction Management in Web Apps

Web apps must ensure database operations are atomic. If a payment deducts from one account but fails to credit another, the entire transaction must roll back.

In Django: with transaction.atomic(): block ensures either all operations succeed or all are rolled back.

📝 ORM Advantages

ORM advantages: Database-agnostic (switch DB with one config change), less SQL errors, automatic schema migrations, cleaner code, built-in protection against SQL injection. Disadvantage: can be slower than optimized raw SQL for complex queries.

Unit 07

Web Frameworks & UI Design Principles

Structure your applications and design interfaces that users love.

MVC — Model-View-Controller

📦
Model
Data + Business logic. Interacts with database. No knowledge of View or Controller. Example: User class.
🖼
View
UI presentation layer. Renders data from Model. Templates / HTML pages. No business logic.
🎮
Controller
Handles user input. Calls Model, selects View. The glue between Model and View. Route handlers.

Django uses MVT (Model-View-Template) — Django's "View" acts as a Controller, and "Template" acts as the View in classic MVC.

💡 UI Design Quick Rules

Contrast ratio ≥ 4.5:1 for text (WCAG accessibility). 8px grid system for spacing. Max 3 font sizes per page. Primary actions = prominent button; secondary = ghost/outline. White space is not wasted space — it guides attention.

Unit 08

Mobile Computing & Android Development

Factors in mobile development, Android environment, activity lifecycle, and generic UI development.

🔥

Very Important: Android Activity lifecycle, differences between mobile and desktop development, Intent system, and the Android development environment setup appear in most exams.

🔋
Battery & Performance
Mobile apps must minimize CPU/GPU usage. Background tasks, animations, and network calls drain battery rapidly.
📶
Connectivity
Apps must work offline or with intermittent connectivity. Cache data locally. Handle network timeouts gracefully.
📐
Screen Size & DPI
Huge variety of screen sizes and pixel densities. Use responsive/adaptive layouts (dp/sp units in Android).
👆
Touch Interface
Touch targets ≥ 48×48dp. Gestures (swipe, pinch). No hover state. Fat finger problem — enough spacing.
💾
Limited Memory
Mobile RAM is limited. Avoid memory leaks. Release resources in onStop()/onDestroy(). Load images efficiently.
🔒
Security & Permissions
Request only necessary permissions. Encrypt sensitive data. Runtime permissions (Android 6.0+). No storing passwords in plain text.

Mobile Software Engineering

Mobile SE differs from desktop SE in: shorter development cycles, over-the-air (OTA) updates, app store submission & review process, platform-specific guidelines (Material Design for Android, Human Interface Guidelines for iOS), crash analytics from day one.

Android Development Environment

🛠
Android Studio
Official IDE based on IntelliJ IDEA. Layout Editor (drag & drop UI), Logcat, Emulator, Profiler.
☕
Languages
Java (traditional) and Kotlin (modern, official since 2017). Kotlin is now preferred.
📦
Gradle
Build automation tool. Manages dependencies (like Maven). build.gradle — declares libraries, SDK versions.
📁
Project Structure
app/src/main/java — Java/Kotlin code. res/layout — XML UI files. res/values — strings, colors. AndroidManifest.xml — app config.

Activity Lifecycle — The Most Important Android Concept

onCreate()
Activity is being created. Initialize UI, bind data. Called once. setContentView() called here.
onStart()
Activity becomes visible to user (but not interactive yet).
onResume()
Activity is in foreground and user can interact. Start animations, sensors, camera here.
onPause()
Activity partially obscured (another activity comes). Pause animations, release resources you don't need. Commit unsaved changes.
onStop()
Activity no longer visible. Release heavy resources. Save data.
onDestroy()
Activity is being destroyed. Final cleanup. Called before activity is garbage collected.

Intents — Communication Between Components

Explicit Intent: Start a specific Activity/Service by name. Intent i = new Intent(this, SecondActivity.class); startActivity(i);

Implicit Intent: Request an action without specifying component. System finds appropriate app. Example: Intent.ACTION_VIEW to open a URL in the browser.

Passing data: intent.putExtra("key", value) — receive with getIntent().getStringExtra("key")

Exam Strategy

Maximize your score even with limited preparation time.

01
🎯 Most Scoring Topics
Focus on: JavaScript + DOM (20-25%), HTTP/AJAX (15-20%), HTML/CSS/Bootstrap (15%), Android Lifecycle (10%), ORM/Frameworks (10%). These 5 areas cover 70%+ of marks in most universities.
02
⚡ 1-Day Revision Plan
Morning: HTTP + WebSockets + AJAX (2hr). Afternoon: HTML/CSS/Bootstrap + JS/jQuery (2hr). Evening: ORM + MVC + UI Design (2hr). Night: Android Lifecycle + Quick Revision cards (1hr). Reinforce, don't cram new topics.
03
📝 Theory Answer Strategy
Structure: Definition (2 lines) → Key features/list (bullets) → Code example → Comparison table if applicable. Always include a code snippet — even a 5-line HTML/JS example adds 2-3 marks and shows practical knowledge.
04
💻 Solving Code Questions
Step 1: Write the boilerplate (DOCTYPE, html, head, body). Step 2: Add the required element/function. Step 3: Add a comment explaining each part. Step 4: Show sample output if asked. Even partial credit is credit.
05
❓ MCQ Elimination
For MCQs: Eliminate obviously wrong answers (usually 2 can be eliminated). Between remaining 2 — watch for absolute keywords ("always", "never") which are often traps. Pick the most specific/precise answer. GET vs POST MCQs: remember GET=URL, POST=body.
06
🕐 3-Hour Exam Plan
Hour 1: All MCQs + short questions you know well. Hour 2: Long questions — code-writing + theory comparisons (most marks). Hour 3: Android/Mobile theory + review answers. Write neat, structured answers with proper headings.
💙

You've got this. Web Dev is hands-on and logical. The student who can write a basic HTML form, understands GET vs POST, knows what AJAX does, and can describe the Android Activity lifecycle can comfortably score 70%+. Trust your preparation, stay calm, and code confidently.
