Unit 01

Basic Computer Organization & Design

The foundation of how a digital computer is structured, how it stores and processes instructions, and the role of each hardware component.

⭐

Most Important for Exam: Operational concepts, Von Neumann architecture, register types, instruction codes — these appear in almost every CO university exam.

A computer system is an electronic device that accepts input, processes it, stores data and produces output. The most widely used model is the Von Neumann architecture — a stored-program computer where instructions and data share the same memory.

Von Neumann vs Harvard Architecture

FeatureVon NeumannHarvard
MemorySingle shared memory for data and instructionsSeparate instruction and data memory
BusSingle shared busSeparate buses for data and instruction
SpeedSlower (bottleneck)Faster (parallel fetch)
ExampleMost general-purpose computersDSPs, PICs, some microcontrollers
SimplicitySimpler designMore complex

Operational Concepts — The Fetch-Decode-Execute Cycle

Every CPU continuously repeats a fundamental loop:

1. Fetch
CPU reads the instruction from the memory address held in the Program Counter (PC). The instruction is loaded into the Instruction Register (IR). PC is incremented to point to the next instruction.
2. Decode
The control unit decodes the instruction in IR. It identifies the opcode (operation) and operands. Determines which functional units are needed.
3. Execute
The ALU or other units perform the actual operation — arithmetic, logical, data transfer, or branching. Results are stored back to registers or memory.

Instruction Code Format

An instruction code is a group of bits that instructs the computer to perform a specific operation. A typical instruction format:

| OPCODE (bits 15-12) | I (bit 11) | ADDRESS (bits 10-0) |

Opcode: Specifies the operation (ADD, LOAD, STORE, etc.)
I (Indirect bit): 0 = direct addressing, 1 = indirect addressing
Address: Memory address of the operand

💡 Memory Trick

Fetch-Decode-Execute = F-D-E = "First Do Everything". The PC always points to the NEXT instruction — it's incremented during the Fetch stage.

Registers are high-speed storage locations inside the CPU. They hold data currently being processed. Access time is several orders of magnitude faster than RAM.

📝 Status Flags (PSW)

Z (Zero): Set if result = 0. C (Carry): Set if carry out from MSB. V (Overflow): Set if signed overflow. S/N (Sign/Negative): Set if result is negative. P (Parity): Set if even number of 1s. Know these cold — they appear in MCQs constantly.

An addressing mode specifies how the operand (or its address) is determined from the fields of the instruction. Different modes offer trade-offs between instruction size, flexibility, and speed.

💡 Memory Trick

I-D-I-R-RI-D-I-R-S: Immediate → fastest (no memory), Direct → 1 memory access, Indirect → 2 memory accesses, Register → fastest of all (no memory). Speed: Register > Immediate > Direct > Indirect.

Unit 03

Data Representation

How computers represent numbers, characters, and fractions in binary — crucial for numerical questions in exams.

🔥

Guaranteed Numericals: Sign-magnitude, 1's complement, 2's complement conversions, IEEE 754 floating point — numericals from these appear in every exam.

Computers represent negative numbers using special conventions. For an n-bit number:

S-M
Sign-Magnitude Representation
MSB = sign bit (0 = positive, 1 = negative). Remaining bits = magnitude.
Example (8-bit): +25 = 0001 1001, −25 = 1001 1001
Range: −(2ⁿ⁻¹ − 1) to +(2ⁿ⁻¹ − 1). Two representations of zero (−0 and +0). Arithmetic is complex.
Problem: Two zeros, complex arithmetic
1's
One's Complement
Negate by flipping all bits (invert).
Example: +25 = 0001 1001, −25 = 1110 0110
Range: −(2ⁿ⁻¹ − 1) to +(2ⁿ⁻¹ − 1). Still has two zeros (+0 and −0). Addition requires end-around carry.
Still has two zeros — rarely used today
2's
Two's Complement (Most Used)
Negate by: invert all bits, then add 1. OR: subtract from 2ⁿ.
Example: +25 = 0001 1001, −25 = invert → 1110 0110 + 1 = 1110 0111
Range: −2ⁿ⁻¹ to +(2ⁿ⁻¹ − 1). Only ONE representation of zero. Simple addition — no special handling.
Used in all modern computers. Most important!

Fixed Point Representation

The binary point is assumed to be at a fixed location (e.g., after the MSB for fractions, or after all bits for integers). Simple but limited range. Used in embedded systems and DSPs.

Floating Point Representation — IEEE 754

Format: ±M × 2ᴱ where M = Mantissa (significand), E = Exponent.

FieldSingle Precision (32-bit)Double Precision (64-bit)
Sign1 bit1 bit
Exponent8 bits (biased by 127)11 bits (biased by 1023)
Mantissa23 bits (implied leading 1)52 bits (implied leading 1)
Total32 bits64 bits

Bias (Excess) notation: Stored exponent = Actual exponent + Bias. For single precision: Stored = Actual + 127.

Normalized form: 1.mantissa × 2ᴱ — the leading 1 before the point is implied (not stored), giving an extra bit of precision.

📝 IEEE 754 Special Values

Exponent all 0s + Mantissa all 0s = ±Zero. Exponent all 1s + Mantissa all 0s = ±Infinity. Exponent all 1s + Mantissa ≠ 0 = NaN (Not a Number). These are frequently asked in MCQs.

2's Complement Subtraction

A − B = A + (2's complement of B) = A + (B̄ + 1). This reduces subtraction to addition — no separate subtractor needed in hardware!

Overflow detection in 2's complement: Overflow occurs if the carry into the sign bit ≠ carry out of the sign bit. Equivalently: positive + positive = negative, or negative + negative = positive.

Half Adder

Adds two single bits. No carry input.

Sum = A XOR B
Cout = A AND B

Full Adder

Adds three bits (A, B, Carry-in). Building block of all multi-bit adders.

Sum = A XOR B XOR Cin
Cout = (A AND B) OR (B AND Cin) OR (A AND Cin)

Ripple Carry Adder (RCA)

An n-bit ripple carry adder chains n Full Adders in series. The carry output of each stage ripples into the carry input of the next stage.

Advantage: Simple design, easy to implement.

Disadvantage: Slow for large n — worst-case delay is O(n) gate delays because carry must propagate through all stages sequentially.

Carry Look-Ahead Adder (CLA): Pre-computes carries in parallel using Generate (G = A·B) and Propagate (P = A⊕B) signals. Reduces delay to O(log n) — much faster for large word sizes.

💡 Key Formulas

For n-bit RCA: delay = n × tFA. CLA reduces this to O(log n). In an exam: if asked "why CLA is faster" → mention parallel carry generation, O(log n) vs O(n) delay.

Pipelining

The technique that makes modern CPUs fast — overlapping instruction execution to maximize throughput.

🔥

Very Important: Speedup formula, pipeline stages, all three hazard types (structural, data, control) — numericals and theory appear in every exam.

Pipelining is a technique where multiple instructions are overlapped in execution. Like an assembly line — while one instruction is being executed, the next is being decoded, and the one after is being fetched.

Key Formulas

Time without pipeline = n × k × t
Time with pipeline = (k + n − 1) × t
Speedup = (n × k) / (k + n − 1) ≈ k (for large n)
Throughput = n / (k + n − 1) × t

where: n = number of instructions, k = number of stages, t = time per stage

For a large number of instructions, speedup approaches k (number of pipeline stages) — the theoretical maximum speedup.

📝 Example Numerical

5-stage pipeline, 100 instructions, 1ns per stage: Time = (5 + 100 − 1) × 1 = 104 ns. Without pipeline: 100 × 5 = 500 ns. Speedup = 500/104 ≈ 4.8 (close to k=5).

Pipeline hazards are situations that prevent the next instruction from executing during its designated clock cycle, causing pipeline stalls (bubbles).

SH
Structural Hazard
Two instructions need the same hardware resource at the same time. Example: Memory access conflict — one instruction in MEM stage, another trying to fetch from same memory (IF stage).
Solutions: Duplicate resources (separate instruction cache and data cache), stall the pipeline.
Caused by: Resource Conflict
DH
Data Hazard
An instruction depends on the result of a previous instruction that hasn't completed yet.
Types: RAW (Read After Write — true dependency), WAR (Write After Read — anti-dependency), WAW (Write After Write — output dependency).
Solutions: Forwarding/Bypassing (send result directly to next stage), Stalling (inserting NOP), Out-of-order execution.
RAW is most common and most important!
CH
Control Hazard (Branch Hazard)
Caused by branch instructions. When a branch is taken, the instructions already in the pipeline (fetched after the branch) must be discarded (flushed).
Solutions: Branch prediction (static/dynamic), Delayed branching (execute instruction after branch regardless), Speculative execution.
Branch prediction accuracy is key to modern CPU performance
Hazard TypeCauseBest Solution

Data (RAW)Read before write completeForwarding/Bypassing

Memory Organization

Hierarchical memory, cache design, mapping functions, replacement policies — a major exam topic.

The memory hierarchy exploits the principle of locality: programs tend to use recently accessed data and instructions (temporal locality) and nearby data (spatial locality).

LevelTypeAccess TimeSizeCost/bit

Cache Memory — Mapping Functions

Direct Mapping: Each main memory block maps to exactly ONE cache line. Cache line = (Block number) mod (Number of cache lines). Simple, fast, but conflict misses are high.

Fully Associative Mapping: Any main memory block can be placed in ANY cache line. Most flexible, least conflict misses, but expensive — requires parallel search of all tag entries.

Set-Associative Mapping (k-way): Cache divided into sets of k lines. Block maps to a specific set, but can go in any of the k lines within that set. Best of both — balances flexibility and cost. Most commonly used (2-way, 4-way, 8-way).

MappingAddress DivisionFlexibilityHardware
DirectTag | Line | OffsetLowSimple, fast

Set-AssociativeTag | Set | OffsetMediumBalanced (most used)

Cache Replacement Algorithms

⏰
LRU (Least Recently Used)
Replace the block that was least recently accessed. Best practical performance. Expensive to implement exactly.
🎲
Random
Replace a randomly selected block. Simple hardware. Surprisingly good in practice.
🔢
FIFO (First In First Out)
Replace the block that has been in cache the longest. Simple counter-based implementation.
📊
LFU (Least Frequently Used)
Replace the block accessed least often. Requires frequency counter per block.

Write Policies

Write-Through: Every write to cache is immediately written to main memory. Ensures consistency but increases memory traffic. Often used with a write buffer.

Write-Back (Copy-Back): Write only to cache; write to main memory only when the block is replaced (dirty bit set). Reduces memory traffic, but inconsistency risk if system crashes before write-back.

Memory Interleaving

Memory is divided into multiple modules (banks). Consecutive addresses are in different banks. Allows simultaneous access to multiple words, increasing effective bandwidth. Used to hide DRAM latency.

💡 Hit Ratio Formula

Effective Access Time = h × Tc + (1 − h) × Tm, where h = hit ratio, Tc = cache access time, Tm = main memory access time. High hit ratio (~0.95+) means cache is working well.

DMA Operation Steps

1. CPU programs DMA
CPU sets up DMA controller: source address, destination address, byte count, direction (read/write). Then CPU continues its own work.
2. DMA takes bus control
DMA controller requests and acquires control of the system bus (Bus Request / Bus Grant handshake with CPU). CPU is temporarily disconnected from bus (Cycle Stealing or Burst Mode).
3. Data transfer
DMA controller directly transfers data between I/O device and main memory. No CPU involvement in actual byte transfers.
4. Interrupt CPU
When transfer is complete, DMA interrupts CPU to signal completion. CPU can then process the transferred data.

Privileged vs Non-Privileged Instructions

Privileged Instructions: Can only be executed in kernel/supervisor mode. Includes: I/O instructions, HALT, memory management instructions, interrupt enable/disable. Attempting these in user mode causes a protection fault.

Non-Privileged Instructions: Can be executed in user mode (ADD, LOAD, STORE on user memory, arithmetic, branching). Normal user programs use only these.

Interrupt Handling Sequence

1. Interrupt Request
Device asserts interrupt signal on the interrupt request line (INTR). CPU checks at end of each instruction.
2. Context Save
CPU saves current state — PC, PSR/flags, and possibly other registers — on the stack. This snapshot allows resuming later.
3. ISR Execution
CPU jumps to Interrupt Service Routine (ISR) address, found via Interrupt Vector Table (IVT). ISR handles the device.
4. Context Restore
ISR ends with RTI (Return from Interrupt). CPU restores saved state from stack and resumes interrupted program seamlessly.

Role of Interrupts in Process State Transitions

Interrupts are the mechanism by which the OS regains control from running processes and can perform context switching:

▶️
Running → Waiting
Process issues I/O request (software interrupt / trap). OS moves it to waiting queue while device completes transfer.
✅
Waiting → Ready
I/O completes → device interrupts CPU. OS moves process from waiting to ready queue (interrupt tells OS I/O is done).
⏱️
Running → Ready
Timer interrupt fires (preemption). OS scheduler takes over, moves current process to ready and schedules another.
❌
Running → Terminated
Exception (divide by zero, illegal instruction) → OS may terminate process. Software interrupt signals OS of fatal error.
📝 Exam Key Point

Without interrupts, the OS has no way to regain control from a running process (unless it cooperatively yields). The timer interrupt is the foundation of preemptive multitasking. This is a commonly asked conceptual question.

Assembly Language Programming

Practical assembly — MIPS and x86 programs you must know for the practical exam and viva.

🔥

Guaranteed in Practical: Writing basic MIPS/x86 programs, understanding registers and addressing modes, loop and branch constructs — these are lab exam staples.

MIPS Assembly
# MIPS Register Convention # $zero = 0 always $v0-$v1 = return values # $a0-$a3 = arguments $t0-$t9 = temporaries # $s0-$s7 = saved $ra = return address # $sp = stack pointer $gp = global pointer # Program: Sum of numbers 1 to N main: li $t0, 10 # N = 10 li $t1, 0 # sum = 0 li $t2, 1 # counter i = 1 loop: bgt $t2, $t0, done # if i > N, exit loop add $t1, $t1, $t2 # sum = sum + i addi $t2, $t2, 1 # i = i + 1 j loop # jump back done: move $a0, $t1 # move result to $a0 li $v0, 1 # syscall: print integer syscall # Memory: Load and Store lw $t0, 0($s0) # Load word: t0 = Mem[s0+0] sw $t0, 4($s1) # Store word: Mem[s1+4] = t0 lb $t0, 0($s0) # Load byte (sign extended) # Procedure call myFunc: addi $sp, $sp, -4 # Push: allocate stack space sw $ra, 0($sp) # Save return address # ... function body ... lw $ra, 0($sp) # Restore return address addi $sp, $sp, 4 # Pop: deallocate stack jr $ra # Return to caller
📝 MIPS Key Rules

$zero is always 0 — hardwired. $ra holds return address for jal. lw/sw use base + offset. Branch (beq, bne) is PC-relative. Jump (j, jal) is pseudo-direct (26-bit target). Always save $ra before calling another function.

Simulation Tools Used in Lab

MARS (MIPS Assembler and Runtime Simulator): Java-based, step-by-step MIPS execution, register/memory views. Most common in universities.

SPIM: Another MIPS simulator. Lightweight, command-line or GUI.

Logisim / Digital: Digital circuit simulation for datapath design — draw and simulate ALUs, multiplexers, registers, full CPU datapaths.

8086 Emulator (emu8086): Emulates x86 8086 processor with full assembly debugging and memory/register visualization.

QEMU / ARM DS: For ARM assembly simulation and cross-compilation.

Exam Day

Exam Strategy

Maximize your score even with limited preparation time.

01
🎯 Most Scoring Topics
Focus on: Pipelining — speedup formula + hazards (20%), Cache memory — mapping + replacement (15%), Data Representation — 2's complement + IEEE 754 numericals (15%), I/O methods (10%), Addressing modes (10%). These cover 70%+ of marks.
02
⚡ 1-Day Revision Plan
Morning: Fetch cycle + Addressing modes + Registers (2hr). Afternoon: 2's complement + IEEE 754 numericals (2hr). Evening: Pipelining — speedup formula + hazards (2hr). Night: Cache mapping + I/O methods + Revision cards (1hr).
03
📝 Theory Answer Strategy
Structure: Definition (2 lines) → Types/Properties (bullets) → Example → Diagram (pipeline timing, cache mapping, circuit diagram) → Comparison table. A pipeline timing diagram can add 3–5 marks even if partially correct.
04
🔢 Solving Numericals
2's complement: +N → invert → add 1. IEEE 754: write sign, convert to binary, normalize (1.xxx × 2ᴱ), add bias (127) to exponent, write mantissa. Pipeline speedup: (n×k)/(k+n−1). Cache: divide address bits into Tag|Set|Offset.
05
❓ MCQ Elimination
For CO MCQs: absolute statements like "only", "always", "cannot" are often wrong. For hazard questions: identify the TYPE first (structural/data/control), then the solution. For addressing modes: count memory accesses — Immediate=0, Direct=1, Indirect=2+.
06
🕐 3-Hour Exam Plan
Hour 1: All MCQs + short answers you know well (address modes, register names, pipeline stages). Hour 2: Long questions — pipelining numerical + cache numerical + data representation (most marks). Hour 3: I/O theory + assembly + review. Never leave numericals blank — show formula for partial credit.
